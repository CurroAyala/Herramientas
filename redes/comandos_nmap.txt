##########
## NMAP ##
##########

Nmap (Network Mapper) es una herramienta de código abierto diseñada para descubrir dispositivos conectados a una red e identificar qué puertos y servicios tienen abiertos.

nmap <tipo(s) de análisis> [opciones] <objetivo>

Nmap acepta como objetivo hostnames, direcciones IP, redes, etc.

TIPOS DE ANÁLISIS:
    -sS/sT/sA/sW/sM: Análisis TCP SYN/Connect()/ACK/Window/Maimon
    -sN/sF/sX: Análisis TCP Null, FIN, y Xmas
    --scanflags <indicador>: Personalizar los indicadores TCP a utilizar
    -sI <sistema zombi[:puerto_sonda]>: Análisis pasivo («Idle», N. del T.)
    -sO: Análisis de protocolo IP
    -b <servidor ftp rebote>: Análisis por rebote FTP
    -sL: Sondeo de lista (simplemente lista los objetivos a analizar)
    -sP: Sondeo ping (sólo determina si el objetivo está vivo)


OPCIONES:

    · DE ENTRADA
        -iL <archivo_entrada>: Lee una lista de sistemas/redes del archivo.
        -iR <número de sistemas>: Selecciona objetivos al azar
        --exclude <sist1[,sist2][,sist3],...>: Excluye ciertos sistemas o redes
        --excludefile <fichero_exclusión>: Excluye los sistemas indicados en el fichero

    · DESCUBRIMIENTO DE HOSTS:
        -P0: Asume que todos los objetivos están vivos
        -PS/PA/PU [listadepuertos]: Análisis TCP SYN, ACK o UDP de los puertos indicados
        -PE/PP/PM: Solicita un análisis ICMP del tipo echo, marca de fecha y máscara de red
        -n/-R: No hacer resolución DNS / Siempre resolver [por omisión: a veces]
        --dns-servers <serv1[,serv2],...>: Especificar servidores DNS concretos
        --system-dns: Utilizar la resolución del sistema operativo

    · ESPECIFICACIÓN DE PUERTOS Y ORDEN DE ANÁLISIS:
        -p <rango de puertos>: Sólo sondear los puertos indicados
            Ej: -p 22; -p 1-65535; -p U:53,111,137,T:21-25,80,139,8080
        -p-: Sondear tódos los puertos
        -F: Rápido - Analizar sólo los puertos listados en el archivo nmap-services
        -r: Analizar los puertos secuencialmente, no al azar.

    · DETECCIÓN DE SERVICIO/VERSIÓN:
        -sV: Sondear puertos abiertos, para obtener información de servicio/versión
        --version-intensity <nivel>: Fijar de 0 (ligero) a 9 (probar todas las sondas)
        --version-light: Limitar a las sondas más probables (intensidad 2)
        --version-all: Utilizar todas las sondas (intensidad 9)
        --version-trace: Presentar actividad detallada del análisis (para depurar)

    · DETECCIÓN DE SISTEMA OPERATIVO
        -O: Activar la detección de sistema operativo (SO)
        --osscan-limit: Limitar la detección de SO a objetivos prometedores
        --osscan-guess: Adivinar el SO de la forma más agresiva

    · TEMPORIZADO Y RENDIMIENTO:
        -T[0-5]: Seleccionar plantilla de temporizado (los números altos son más rápidos)
        --min-hostgroup/max-hostgroup <tamaño>: Paralelizar los sondeos
        --min-parallelism/max-parallelism <numsondas>: Paralelización de sondeos
        --min-rtt-timeout/max-rtt-timeout/initial-rtt-timeout <msegs>: Indica el tiempo de ida y vuelta de la sonda
        --max-retries <reintentos>: Limita el número máximo de retransmisiones de las sondas de análisis de puertos
        --host-timeout <msegs>: Abandonar un objetivo pasado este tiempo
        --scan-delay/--max-scan-delay <msegs>: Ajusta el retraso entre sondas

    · EVASIÓN Y FALSIFICACIÓN PARA CORTAFUEGOS/IDS:
        -f; --mtu <valor>: fragmentar paquetes (opc. con el MTU indicado)
        -D <señuelo1,señuelo2[,ME],...>: Disimular el análisis con señuelos ("ME" es la IP propia)
        -S <Dirección_IP>: Falsificar la dirección IP origen
        -e <interfaz>: Utilizar la interfaz indicada
        -g/--source-port <numpuerto>: Utilizar el número de puerto dado
        --data-length <num>: Agregar datos al azar a los paquetes enviados
        --ttl <val>: Fijar el valor del campo time-to-live (TTL) de IP
        --spoof-mac <dirección mac/prefijo/nombre de fabricante>: Falsificar la dirección MAC
        --badsum: Enviar paquetes con una suma de comprobación TCP/UDP falsa

    · SALIDA:
        -oN/-oX/-oS/-oG <file>: Guardar el sondeo en formato normal, XML, script kiddie, y Grepeable, respectivamente.
        -oA <nombre_base>: Guardar en los tres formatos principales al mismo tiempo
        -v: Aumentar el nivel de mensajes detallados (-vv para aumentar el efecto)
        -d[nivel]: Fijar o incrementar el nivel de depuración (Tiene sentido hasta 9)
        --packet-trace: Mostrar todos los paquetes enviados y recibidos
        --iflist: Mostrar interfaces y rutas (para depurar)
        --append-output: Agregar, en vez de sobreescribir, a los archivos indicados con -o.
        --resume <archivo>: Retomar un análisis abortado/detenido
        --stylesheet <ruta/URL>: Convertir la salida XML a HTML según la hoja de estilo XSL indicada
        --webxml: Referenciar a la hoja de estilo de Insecure.Org para tener un XML más portable
        --no-stylesheet: No asociar la salida XML con ninguna hoja de estilos XSL

    · MISCELÁNEO:
        -6: Habilitar análisis IPv6
        -A: Habilita la detección de SO y de versión
        --datadir <nombreDir>: Indicar la ubicación de los archivos de datos Nmap personalizados.
        --send-eth/--send-ip: Enviar paquetes utilizando tramas Ethernet o paquetes IP "crudos"
        --privileged: Asumir que el usuario tiene todos los privilegios
        -V: Muestra el número de versión
        -h: Muestra esta página resumen de la ayuda


ESCANEOS MÁS COMUNES:

    1. TCP Connect (-sT): verifica el estado de los puertos intentando completar un saludo (handshake) TCP.
        · Si responde con SYN/ACK, está abierto.
        · Si responde con RST, está cerrado.
        · Si no hay respuesta (o el cortafuegos la bloquea), se considera filtrado.

    2. SYN (-sS): también conocido como <<semiabierto>> ("half-open") o <<sigiloso>> ("stealth"), identifica puertos abiertos sin llegar a completar la conexión. Cuando el objetivo responde con un SYN/ACK, se envía inmediatamente un reseteo (RST) para abortar el proceso. Para los puertos cerrados o filtrados, funciona exactamente igual que el TCP Connect.
    * Requiere permisos de administrador.
    * Puede llegar a tumbar servicios que sean inestables.

    3. UDP (-sU): analiza puertos basados en este protocolo, sin handshake previo. Al no haber confirmación de conexión, es mucho más difícil y lento.
        · Si devuelve un mensaje ICMP de puerto inalcanzable, está cerrado.
        · Si no hay respuesta (lo habitual), Nmap lo reintenta y lo marca como open|filtered (podría estar abierto o bloqueado por un cortafuegos).
        · Si hay una respuesta UDP (muy poco común), el puerto está abierto.

    4. NULL (-sN), FIN (-sF), XMAS (-sX): envían paquetes TCP "malformados" (sin el flag SYN) con el objetivo de evadir cortafuegos que bloquean los intentos de nuevas conexiones. NULL no activa ninguna flag en el paquete, FIN activa únicamente la flag FIN y Xmas activa las flags PSH, URG y FIN. Para los tres casos:
        · Si responde con RST, el puerto está cerrado.
        · Si no hay respuesta, se marca como open|filtered (no se sabe si está abierto o protegido por un cortafuegos).
        · Si responde con un error ICMP de inalcanzable, está filtrado.

    5. ICMP Connect (-sn): conocido como "ping sweep" o <<barrido de pings>>, sirve para hacer un mapa rápido de la red y descubrir qué equipos están activos sin llegar a escanear sus puertos. Se ejecuta indicando un rango de IPs con un guion (ej. 192.168.0.1-254) o con notación CIDR (ej. 192.168.0.0/24).



# NMAP SCRIPTING ENGINE (NSE)
Es una herrmamienta adicional, incluida en nMap, que permite a los usuarios escribir y compartir scripts simples, utilizando el lenguaje de programación Lua, para automatizar una amplia variedad de tareas. Es una biblioteca muy extensa, cuyas categorías principales son:
    - Safe: no afectan al objetivo.
    - Intrusive: podrían afectar al objetivo.
    - Vuln: escaneo de vulnerabilidades.
    - Exploit: intentan explotar una vulnerabilidad.
    - Auth: intentan eludir la autenticación de servicios en ejecución.
    - Brute: intentan descifrar credenciales por fuerza bruta.
    - Discovery: intentan consultar los servicios en ejecución para obtener más información sobre la red.

- Ejecutar un script:
    nmap [...] --script <nombre_script> [--script-args <argumento>=<'valor'>,...]

- Obtener ayuda con un script:
    nmap --script-help <nombre-script>

- Buscar un script en línea: https://nmap.org/nsedoc/

- Buscar un script local:
    grep "<búsqueda>" /usr/share/nmap/scripts/script.db
    ls -l /usr/share/nmap/scripts/<búsqueda>

- Instalar nuevos scripts:
    (En Linux, primero actualizar repositorios locales.)
    sudo wget -O /usr/share/nmap/scripts/<nombre_script>.nse

- Actualizar la base de datos local de scripts:
    (Necesario tras instalar nuevos scripts)
    nmap --script-updatedb



# TÉCNICAS DE EVASIÓN DE CORTAFUEGOS

- Omitir ping: -Pn
- Fragmentación automática (dividir los paquetes en trozos más pequeños): -f
- Fragmentación manual, especificando el tamaño de los trozos: -mtu <tamaño>
    * El tamaño debe ser múltiplo de 8
- Introducir pausa entre los paquetes: --scan-delay <tiempo>ms
- Enviar paquetes con un checksum inválido: --badsum
